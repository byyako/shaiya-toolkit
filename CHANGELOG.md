### shaiya (CLI)

- `shaiya info` describes a WAV, an Ogg Vorbis file, a JPEG and a PNG by their headers, found by content (a file named `.saf` is still reported as SAF data, test `a_saf_whose_first_file_is_a_sound_or_a_picture_is_still_a_saf`; a JPEG whose frame header lies after the first 64 KiB says so, test `a_jpeg_whose_frame_header_lies_past_the_first_64_kib_says_so`) (for example "WAV, PCM 16 bit, 2 channels, 44100 Hz, 1.0 s, N bytes"). Tests: `a_wav_is_described_by_its_header_whatever_its_name`, `an_ogg_is_described_by_its_vorbis_header`, `a_jpg_and_a_png_are_described_by_their_headers`.
- `shaiya anim export --format obj|bvh` writes a `.3DO`, `.3DE` or (at rest) `.3DC` as Wavefront OBJ (`-o x.obj`, with a `.mtl` of texture names beside it when the mesh names a texture) and an `.ANI` as BVH (`-o x.bvh`, one frame per whole key at 30 per second, ZXY rotations, a synthetic `Shaiya_Root` for a skeleton with two or more roots; a non-root bone that moves relative to its parent is exit 3 unless `--drop-translation` leaves its motion out; `--scale F`). glTF, OBJ and BVH are a lossy view of the game file; the JSON export stays the byte-exact round trip. Validated offline: no other program opening these files was tried. On US EP4.5 (opt-in) 3,163 of 3,169 readable `.3DO`, `.3DE` and `.3DC` files are written as OBJ (6 `.3DC` refused for a vertex that is not finite) and 229 of 3,509 `.ANI` files as BVH by default (3,280 refused, 3,278 of them for a bone that translates relative to its parent, which includes the real roots of a rig with two or more roots; 3,245 of the refused are written with `--drop-translation`, the other 35 hold a value that is not finite or a mirrored matrix). Tests: `a_3do_round_trips_through_obj`, `obj_flips_v_and_winding_and_back`, `a_known_three_joint_pose_writes_the_expected_channels_zxy`, `the_bvh_poses_like_the_games_pose`, `euler_unwrap_across_180`, `two_roots_get_a_synthetic_root`, `a_translating_non_root_bone_is_refused_unless_dropped`, `frame_time_is_one_thirtieth`, `an_ani_exports_as_bvh_and_the_meshes_as_obj`, `the_export_outputs_follow_the_json_rules`, `every_us_client_mesh_exports_obj_and_a_3do_or_3de_comes_back`, `every_us_client_ani_exports_bvh_or_is_refused_by_kind_and_comes_back`.
- `shaiya anim import IN.obj -o OUT.3do|.3de` reads a Wavefront OBJ as a new file (triangles and quads, negative indices, one material, missing normals computed and said; a missing texture coordinate, a second material or more than 65,535 vertices is exit 3 with the line; the `.mtl` is never opened) and `shaiya anim import IN.bvh -o OUT.ani --like TARGET` reads a BVH laid out as the export writes it (joints `Bone_NNN`, ZXY channels, `Frame Time` 1/30, only the root with position channels, every `OFFSET` equal to the like file's reference translation, a `Shaiya_Root` with an offset or a move refused, a rotation track dropped only when the like file's bone is posed the same without it (a scaled bone with rotation keys keeps its track); exit 2 without `--like`; written only when the `.ANI` passes the `compare` check, exit 1 otherwise). Validated offline; an `.ANI` comes back with the same poses, not the same bytes. Tests: `quads_and_negative_indices_import`, `missing_normals_are_computed_and_said`, `missing_uv_or_two_materials_are_refused`, `more_than_65535_vertices_are_refused`, `malformed_obj_is_an_error_not_a_panic` (also a `v` with a fourth number other than 1), `a_scaled_bone_with_constant_rotation_keys_keeps_its_rotation_track`, `obj_import_never_opens_mtllib`, `malformed_obj_is_an_error_not_a_panic`, `bvh_round_trips_to_ani_poses_within_1e_4`, `bvh_joints_that_do_not_match_the_rig_are_refused`, `another_channel_order_or_frame_time_is_refused`, `a_non_root_position_channel_is_refused`, `malformed_bvh_is_an_error_not_a_panic`, `bvh_import_without_like_exits_2`, `a_bvh_import_that_does_not_pass_exits_1_and_writes_nothing`, `bvh_import_outputs_follow_the_import_rules`, `a_refused_obj_is_exit_3_with_its_reason_and_nothing_is_written`, `an_obj_comes_back_as_the_same_3do_and_3de`.
- `shaiya anim export --format gltf|glb` writes an `.ANI`, a `.3DC` (with `--anim ANI` for the animations that move it), a `.3DO` or a `.3DE` as glTF 2.0 (`-o x.gltf` with a `.bin` beside it, or `-o x.glb`; `--out-dir` writes one per file), with `--allow-lossy`, `--pad-end` and `--texture-uri-base DIR`. glTF is a lossy view of the game file; the JSON export stays the byte-exact round trip. The file is checked by the toolkit before it is written (structure, finite numbers, weights, quaternions, and the skinned pose against the toolkit's renderer; a file where `--allow-lossy` projected something is not posed, and the output says so). A file that cannot be written is exit 3 and the reason names the bone or vertex. Validated offline: the Khronos glTF validator 2.0.0-dev.3.10 reports no errors on the output for the synthetic test files and for one US EP4.5 rig; Blender was not tried. Tests: `a_mesh_with_an_animation_becomes_gltf_and_bin_or_one_glb`, `the_output_rules_are_those_of_the_json_export`, `a_file_that_cannot_be_written_is_exit_3_and_the_reason_names_the_bone`, `out_dir_writes_one_gltf_and_bin_per_file_and_reports_the_rest`, `from_an_archive_the_source_is_the_archive_path`, `the_help_carries_the_lossy_view_sentence`, `the_khronos_validator_accepts_the_output`.
- `shaiya anim import IN.gltf|IN.glb -o OUT.ani|.3dc|.3do|.3de` reads a glTF 2.0 file as a new game file, with `--like TARGET [--from ARCHIVE]` (required for an `.ANI` and a `.3DC`, refused for a `.3DO` or `.3DE`: exit 2), `--map FILE` (lines `node name = bone index`; nodes named `Bone_NNN` of any width need none), `--reduce-influences`, `--reduce` and `--keys exact`. An `.ANI` takes its skeleton and first field from `--like` and is written only when it passes the `compare` check (exit 1 and `nothing written` otherwise); a `.3DC` only when its bone count is the like file's; the output rules are those of the JSON import (exit 4). A file the importer cannot take is exit 3 with a reason that names the node, bone or vertex (scale on a bone, morph targets, more than two influences, sparse or normalized or quantized data, a required extension, a buffer that is a URL or outside the folder, a skeleton that is not the like file's, and more). glTF is a lossy view of the game file; an `.ANI` comes back with the same poses, not the same bytes, and a `.3DC` the toolkit exported comes back byte for byte. Validated offline. Tests: `a_gltf_comes_back_as_the_same_3dc_and_an_ani_that_passes`, `import_without_like_for_ani_or_3dc_exits_2`, `an_imported_ani_that_does_not_pass_exits_1_and_writes_nothing`, `the_import_outputs_follow_the_import_rules`, `a_refused_gltf_is_exit_3_with_its_reason_and_nothing_is_written`, `import_help_carries_the_lossy_view_sentence_and_the_flags`, and on US EP4.5 (opt-in) `us_client_gltf_round_trips` (16 rigs' first animations and 96 default parts: every `.3DC` byte for byte, every `.ANI` passes and poses within 1.1e-6) and `every_exportable_us_ani_imports_back_with_keys_exact` (3,462 of 3,509 `.ANI` files, the other 47 refused by the export).
